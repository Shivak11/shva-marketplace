# Programme Architecture

## Use this reference when

Use this reference to turn a brief into a linked executive programme. Use MDP Architect when the output needs both a programme spine and two or more connected session surfaces. Hand a raw source request to `mdp-source-finder`, a one off keynote or script to `teaching-designer`, and a standalone worksheet to `worksheet-generator`.

## Build the spine before any chapter

1. Read the current teaching workspace rules, the programme README, its source ledger, and the latest rendered artifact.
2. Write one programme question. It must describe the capability the room will build, not the topic it will hear about.
3. Name the carried participant artifact. It must gain one usable layer in each session.
4. Sequence sessions as a decision journey: disturbance, map, mechanism, test, redesign, commitment. Do not sequence by a list of fashionable concepts.
5. Give each session one question that makes the next session necessary.
6. Build the official timetable separately from the facilitation capacity. Do not silently change client times to fit a richer design.

## Required programme plan table

Place the programme plan table immediately after the cover in a participant HTML artifact. Each row must contain:

| Field | Requirement |
| --- | --- |
| Session | Number, title, official duration, and position in the journey. |
| Central question | One question with a practical decision at stake. |
| Organizational disturbance | The situation that opens the session. |
| Carried artifact | The exact participant output that enters or leaves the session. |
| Core mechanism | One framework, map, or test that earns its place in the case. |
| Commitment | What participants decide before any AI challenge. |
| Handoff | The unresolved question and artifact version that the next session receives. |

Do not use the table as a catalogue. A reader should see why Session 4 could not happen before Session 2.

## Session design rules

Each session must contain one sustained case. Give the case a concrete organizational decision, actors, constraint, incomplete evidence, and consequence. Return to it at decisive moments rather than through a mechanical callback quota. Permit one to three bounded lateral examples when each clarifies a different move the main case cannot show. Every example must return to the organisational question it was chosen to explain.

Build a protected 90 minute core. Allocate the remaining 30 minutes as named depth reserves that deepen the existing case, mechanism, or artifact. Every reserve needs a rejoin point that restates the question and identifies the artifact state participants should have before the next core move.

Use this timing ledger for every session:

| Lane | Must show |
| --- | --- |
| Core, 90 minutes | Required moves, their timing, the participant output, and the next question. |
| Depth reserve, 30 minutes | Trigger for use, added move, minutes, and an explicit rejoin line. |
| Official timetable | Client committed start, end, and break details. Keep it separate from the capacity ledger. |

## Architecture completion check

Do not draft a chapter until all sessions have a central question, carried artifact, commitment point, source need, and handoff. Reject a programme that has topic labels but no artifact progression, or sessions that can be reordered without changing the learner's work.

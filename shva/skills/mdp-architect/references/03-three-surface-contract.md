# Three Surface Contract

## Non negotiable rule

Book Chapter, Teaching Script, and Slide Content are different compressions of one session. They must use the same central question, case, claims, mechanism labels, participant commitment, AI challenge, exercise, filled edition, and transition.

Use the canonical IDs from `02-session-content-model.md` in all three surfaces. A surface may omit detail. It may not introduce new meaning.

## Book Chapter

Write connected prose that can be read without a facilitator.

- Use 2,500 to 3,200 narrative words, plus a 400 to 600 word chapter end workbook unless the brief sets a different length.
- Use no more than three internal headings.
- Begin with the organizational disturbance, not a definition, agenda, or explanation of how the modes work.
- Sustain one case. Use at most one brief lateral example.
- Use one inline diagram only after the reader has experienced the tension it resolves.
- Use no body callout card system, repeated margin labels, repeated working rules, or facilitation tags.
- Keep emphasis scarce. Use no more than two memorable lines.
- End with a practical workbook and a question that opens the next chapter.

The Book surface contains no timing, speaker instruction, recovery move, source ledger, prompt logic, or tool policy. Put citations in a quiet source note only when the factual claim needs one.

## Teaching Script

Preserve the Book sequence and shared language. Add only delivery information:

- first person spoken lines in Shiva's direct style
- minute ranges and the 90 minute core timing ledger
- room move, likely participant response, and recovery move
- commitment instruction before the AI challenge
- 30 minutes of depth reserves with trigger and explicit rejoin
- AI use boundary and a safe synthetic or redacted input reminder

Do not turn the script into a second chapter or add a new framework because it might be useful live.

## Slide Content

Compress the same session into six to ten visual beats.

- One slide may carry one question, scene, claim, diagram stage, participant move, or transition.
- Reuse exact case names, framework labels, and artifact names from the canonical model.
- Put the participant commitment before any AI comparison or reveal.
- Treat the filled edition as a hidden reveal. Never show it before the participant has had a chance to work.
- Keep source names and provenance out of participant slides unless the requested artifact is a source appendix.

## Workbook and filled edition

The chapter end workbook is a real procedure, not a reflection prompt. It must state the starting material, numbered moves, time or output expectation, decision boundary, and debrief question. It may have an offline lane and an optional ChatGPT lane, but participants must make the first map before using AI.

Provide a realistic completed version of the same exercise. Keep it behind an intentional control labeled plainly, such as `Show a filled edition`. The control must begin closed, work with keyboard input, and not alter the participant's original exercise text.

## Semantic parity check

Before release, compare every surface against the canonical model.

| Check | Pass condition |
| --- | --- |
| Central question | Identical intent and wording. |
| Case | Same actors, stakes, constraint, and resolution. |
| Claims | Every claim points to a canonical ID. |
| Diagram | Same ordered labels and causal meaning. |
| Exercise | Same artifact, commitment, and debrief. |
| AI | Same challenge and boundary, after commitment. |
| Transition | Same next question and carried artifact state. |

If a slide needs an additional idea, improve the canonical model and revise all surfaces. Do not patch the slide alone.

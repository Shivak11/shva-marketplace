# 01 - Intake questions (Stage 1)

Never assemble from a one-line brief. Use AskUserQuestion (at most 4 questions per call, 1 to 2 calls). Offer sensible default options and let Shiva add free text. Only ask what the brief has not already answered.

Learn at minimum:

1. **Topic.** What is the course, MDP, FDP, or workshop about? This sets the keyword and tag query in Stage 2. If the brief is broad ("GenAI for managers"), ask for the sharper angle (workflows, governance, a function, agents).
2. **Audience function and seniority.** Marketers, PMs, finance, HR, faculty, mixed, or CXO. Senior leaders lean toward watch-a-demo beats. A functional cohort with laptops leans toward install-it-yourself labs and domain-specific skills. This decides show vs make and which skills are relevant.
3. **Format: cohort vs self-paced.** A live cohort session needs labs and demos timed for the room. A self-paced program can lean on repos and pre-reads participants work through alone. Most repos assume self-paced, so a cohort brief means flagging what needs re-staging.
4. **Show vs make.** Confirm the default posture: do participants watch demos, or install and run skills themselves? Default to make when friction is low. Senior audiences often want show.
5. **Session length.** A 90-minute session, a half day, a full day, or a 9-to-11-session program. This bounds how many beats and how many items per beat the pack should carry.
6. **Which beats are needed.** Ask which session beats this brief actually needs filled: hands-on lab, opening hook, case study, live demo, pre-read or post-read, course scaffold to borrow. A 90-minute session may need only a hook, a lab, and a pre-read. A full program may need all six plus a scaffold. Do not fill beats the brief does not ask for.

After intake, do not assemble from memory. Query live first (Stage 2: Raindrop plus the wiki map), then re-index for the brief (Stage 3), then recommend the anchor skills (Stage 4).

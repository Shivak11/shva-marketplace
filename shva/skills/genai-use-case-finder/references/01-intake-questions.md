# 01 - Intake questions (Stage 1)

Never fill the matrix from a one-line brief. The quality of the portfolio is set here, in how precisely you pin down the process, the data reality, and the risk exposure. Use AskUserQuestion (at most 4 questions per call, 1 to 2 calls). Offer sensible default options and let the user add free text. Only ask what the brief has not already answered.

This is an analysis intake, not a teaching intake. You are not asking how to teach the method. You are gathering the facts you need to RUN it on a real organization.

Learn at minimum:

1. The unit of analysis. What exactly are we mapping? A function (claims, month-end close), a single process (the hiring funnel), an org, or a whole industry. If the user names something broad ("use AI in finance"), narrow it to one process before you start. A portfolio for "finance" is vague. A portfolio for "month-end close at a mid-size manufacturer" is sharp.

2. The value stream. Ask the user to list the steps of the process, roughly 5 to 9, from trigger to outcome. If they cannot, ask who would know, or reconstruct a plausible stream from the industry and flag it as your assumption to confirm. This is the raw material for Lens A.

3. The decisions underneath. What decisions does this process exist to make? (For claims: is it covered, is it fraud, how much, pay or contest.) This seeds Lens B. If the user only gives steps, infer the decisions and confirm them.

4. Data reality. How clean and accessible is the data each step would need? Is it in one system or scattered across spreadsheets, email, and PDFs? Data readiness carries the heaviest weight in the feasibility score, so a vague answer here weakens the whole portfolio. Push for specifics.

5. Risk and regulatory exposure. What is the cost if the AI is wrong on this process? Is the work regulated (adverse-action law, audit and SOX, data protection, safety)? Are decisions reversible? This sets the risk veto and tells you which candidates can never go past assist-only.

6. Deliverable format. Confirm what to produce: the structured markdown portfolio (the default and primary output), the one-page signed worksheet, and whether the user also wants the optional aesthetic HTML 2x2. Default to the markdown portfolio plus the worksheet when ambiguous, and confirm before building HTML.

## A note before you ask

If the user actually wants to TEACH use-case discovery (run a session, build a keynote, hand participants a fillable worksheet), this is the wrong skill. Say so and hand off: teaching-designer makes the facilitator keynote and session, worksheet-generator makes the participant worksheet. This skill fills the matrix for one real organization. State that boundary early so the conversation does not drift into lesson design.

## After intake

Do not jump to the portfolio. Run MAP, then GATE every candidate, then SCORE, then SEQUENCE, in order. See `references/02-discovery-and-gate.md` and `references/03-score-and-sequence.md`. If a fact is missing (data readiness, a regulatory detail), name the assumption you made rather than leaving the cell blank.
